# Private modular learning workflow

All commands below are developer tools, not website uploads. Keep their inputs/outputs outside the public repository. Nothing calls an AI provider, changes an installed curriculum pointer, deploys production or grants owner approval.

## Authoring and review

1. Receive explicit structured source/lesson input through the owner's authorized private channel. Do not fetch ChatGPT conversations or reconstruct missing pages.
2. Validate the Schema V3 graph. Keep old entity IDs/versions immutable; create a new revision for substantive edits. Compose canonical topics rather than copying evidence into a book-specific lesson.
3. Run `node scripts/content/prepare-ingestion.mjs PRIVATE_BUNDLE EXPLICIT_INPUT.json NEW_PRIVATE_PROPOSAL.json`. It compares exact normalized claims, titles/aliases and explicit relationships. It emits deterministic private proposals/diffs, including unresolved source/alias cases. Split/merge/new-lesson decisions are author-supplied proposals, never inferred semantic truth. No proposal mutates the repository, transfers credit or publishes itself.
4. Review each proposal, source rights, edition/printed-page status, objectives, examples, prediction/debrief, answer criteria and both platform rubrics. Conflicting or missing evidence needs an explicit technical decision. Preserve original records and unresolved gaps. Use `private-review-sheet.mjs` for a readable private sheet.
5. `preparePublication` generates an **unapproved** review manifest binding the exact ordered bundle, previous bundle, content diff and grading diff hashes. Record separate technical, educational, owner and source-rights attestations with reviewer/time/rationale. Source rights are per edition; unknown editions require an explicit acceptance, never a guessed label. Locator review distinguishes preserved citations from independent verification. These attestations are local review records, not authenticated signatures or a safety certification.
6. Produce a closed learner bundle containing published revisions and reviewed source data, keeping private drafts/proposals separately. `node scripts/content/publish-reviewed-bundle.mjs PRIVATE_BUNDLE PRIVATE_MANIFEST NEW_PRIVATE_OUTPUT [PREVIOUS_BUNDLE]` rejects unsupported graphs/assets, altered immutable versions, missing objective/safety/platform coverage, unreviewed evidence, rights/review/hash failures and secret/storage references. It writes immutable local files and rollback metadata with `activated:false`. No release is authorized by export.
7. Generate a new private preview with `private-lesson-preview.mjs`; no credentials or network curriculum service is needed. Both presentation profiles use the same content, question instances and private journal. Draft practice never awards mastery. Only a matching approved publication permits explicitly selected graded sessions. Synthetic fixtures test that path; the Resistors/DMM candidates are still drafts.

Schema V3 never passes through the old schema-1/2 importer. The current public staging application/73 assets and old grading remain unchanged until a separately reviewed cutover.

## Private learning storage and recovery

`PrivateHostStorage` binds every document to an explicit learner UUID and safe namespace. Host adapters implement atomic compare-and-swap, immutable hashed revisions, retained stale candidates, recovery export/import and explicit restore. There is no timestamp-only winner. Imported heads disagreeing with an existing head are retained for review; the learning journal merges immutable attempts and withholds disputed credit. A consistent owner-edited JSON file is not cryptographically authenticated; this is local private learning, not a remote certification system.

- Browser/private webview: `hosts/browser-private-storage.js` uses a separate IndexedDB database. The preview creates a device-local private learner stream; it does not migrate the production account or browser progress. Private recovery explicitly imports/switches stream identity, retaining other streams. Export the recovery JSON outside the browser before clearing storage. The learning export contains exact submitted circuit snapshots but not every independent project or device layout; export projects separately through the existing project manager.
- Optional Node host: `scripts/content/private-file-storage.mjs` uses a new explicitly chosen owner-only directory outside the repository. It atomically replaces hashed JSON, retains pre-write backup files and interrupted pending candidates. Exclusive locks prevent simultaneous writers. A stale lock is never removed automatically. Inspect/export the directory and verify no process is running before an owner-controlled repair. Corrupt primary documents fail closed rather than resetting to an empty learner.
- File recovery: preserve the entire directory first. Validate a chosen backup with `validatePrivateDocument`; reopen it in a fresh private directory via `importRecovery` to verify counts/identity/attempts. Only then choose an explicit restoration in the host. Do not replace a corrupt primary automatically, delete competing copies or silently activate an imported head. Browser recovery uses the same hash/identity envelope.

The journal freezes template, instance, version/hash, seed/parameters, submitted answer or actual circuit/bands, grading result, purpose, platform/module, attempt/time and review schedule. Repeated practice contributes no grade events. New revisions cannot reinterpret old results. Existing common 80% plus safety and 1/7/21-day rules remain; desktop/mobile grades are independent and either-platform is the default practical policy. Conflicting attempts need explicit resolution before credit; a friendly conflict-resolution UI is still pending.

No cloud transport, production Supabase access, native profile copying or paid service is enabled. File adapters are implemented/tested independently; neither native shell has adopted a permanent storage transport. Android packaging, account-linked identity, encryption-at-rest and cross-device transport remain separate design/approval work. Device layout stays separate from learning/project content. Full-document revision history and backups currently favor preservation over storage efficiency; reviewed compaction is future work.

## Recovery of private authoring inputs

Workspace files are ephemeral. The owner must download and retain the private recovery ZIP in a private backed-up location; a local path/hash alone is not verified external retention. Verify the outer ZIP SHA-256, extract into a new private folder, verify every `SHA256SUMS.json` entry, and reload each bundle through `readPrivateBundle`. Preserve unknown legacy fields in the raw structured exports. Use the included commit/source files to reproduce the local preview. No raw PDF or real learner record belongs in this authoring archive or public CI screenshots.

Owner educational/usability acceptance, source review, all 967 mapping decisions and exact V3 deletion-scope approval remain blockers. Keep production V2/V1, Git history and current learner data intact. Reverting a frontend does not restore data compatibility; retain versioned readers/recovery exports when rolling back new private records.
