# Shared electronics foundation v1

`circuit-model.js` separates electrical state from views: stable nodes, components, explicit terminals, wire IDs/closed state, source/resistor properties, power/open state and instrument probe connections. `solveDC` uses modified nodal analysis; `measureVoltage` derives red-minus-black from that solved state. The model is JSON serializable and versioned by `content/circuit.schema.json`. Proof of concept is 5 V and two 1 kΩ resistors: source 5 V, output 2.5 V, current 2.5 mA. Open R1: output 0 V via R2. Open R2: output 5 V through R1 and the ideal unloaded meter. Both open: floating output, unknown reading. Reversed probes reverse the sign.

Tests compare 36 divider combinations against analytic voltage/current, KCL and energy balance; cover node merging, source shorting/redundancy, power removal, floating states and unsupported components. Positive resistances 0.001 Ω–1 GΩ, source magnitude ≤24 V, at most 64 nodes/128 components/256 wires bound this educational solver. These are implementation/low-voltage limits, not lesson count rules. No AC, transients, semiconductor models, tolerances, instrument loading, current/resistance mode or hardware control is supported. Floating differential circuits are conservatively reported unknown even when some internal differential relationships are constrained.

Beginner/intermediate/advanced and educational/instrument presentations use exactly the same circuit and solver. Advanced presentation does not imply advanced physics. The new workspace reuses `dmm-widgets.js#visualDMM` and `lab-visuals.js#circuitSvgFrame`; existing scenario widgets keep their historical behavior. The circuit view shows component terminals by named electrical node. It is a bounded interactive circuit view, not a physical breadboard placement editor. Existing breadboard graphic and interaction remain registered for reuse. A future scope must use this model/analysis interface, not a third separate engine.

## Established engine research

Read the current [ngspice README](https://github.com/ngspice/ngspice/blob/master/README) and [shared-library interface](https://github.com/ngspice/ngspice/blob/master/src/include/ngspice/sharedspice.h) on 2026-10-14. ngspice combines Spice3, Cider and Xspice; its C interface initializes callbacks, accepts circuit lines and exposes result vectors. It is a suitable candidate for a later adapter investigation. No engine was downloaded/built/integrated, no browser/WASM performance or mobile suitability was measured, and the header's modified BSD notice is not a complete dependency-license audit. Evaluate worker isolation, portable builds, model licensing, bundle/startup costs, deterministic snapshots, offline use, command restrictions and electrical regression fixtures before selection. Do not accept arbitrary user/tutor SPICE commands or file directives.

## Project persistence

`content/project.schema.json` and `project-store.js` define independent project identity/metadata, circuit, inventory, versioned widget instances, instrument settings, measurements, notes, experiment state, snapshots and optional lesson references. Project data uses eu_projects_v1; lesson progress and its existing scope/IDs/reviews/backups are unchanged. Device-focused pane choices use eu_workspace_layout_v1 and are not project content.

Local saves use browser locks and revision comparison. A stale write preserves the current project plus an explicit incoming conflict copy and pauses workspace autosaving. Recovery export includes raw storage and the unsaved view. Unknown versions/corrupt storage fail closed; the original is retained. Named snapshots restore circuit, instruments, settings, notes, measurements and experiment state without touching grades. Unsupported lock environments require manual experiment export. Storage quota failures remain visible and the unsaved view can be exported.

Foundation workspace uses side-by-side circuit/meter panels on desktop and selectable focused panes on phones, with native probe selectors and 44px controls. It supports one project and imports only the matching divider-project identity; import/export is ordinary local project JSON, unrelated to retired textbook ingestion. Arbitrary project browsing, sharing, attachments, cloud sync, cross-device merge, dockable/resizable panels, physical breadboard editing, transient oscilloscope and full conflict-resolution UI are deferred. This is local-first groundwork, not a completed synchronized project service. Concurrent local state is preserved; there is no promise of cross-device synchronization.

## Future tutor

`tutor-contract.js` accepts explicitly supplied validated project state. Notes are excluded unless requested. It gives no attachment/file/history access. Supported proposals change bounded resistor/source properties or open-state, verify the original circuit before applying, preview before/after, require explicit approval and return an undo copy. No AI backend or paid call is implemented. Future handlers still need independent authentication, budgets, proposal/owner binding and persistence approval. The retained floating tutor UI cannot dispatch even with an injected client.
