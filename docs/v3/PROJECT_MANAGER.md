# Personal projects — local-first v1

The manager builds on the existing versioned ProjectStore. Projects have independent stable IDs, names/descriptions, search, duplication, divider/breadboard/blank templates, notes, component inventory, instrument settings, recorded measurement contexts, snapshot/experiment state and JSON import/export. Project keys stay separate from lesson progress; duplicating a project never copies grades.

Deletion is a recoverable document state, not key removal. The locked revision increments and the full document remains in recovery. Stale tabs cannot save over a deleted project or silently recreate its identity. Restoration also uses a revision check. Conflicts must be reviewed before deletion. Duplicate projects get new identities; snapshot/component IDs remain scoped to their project. New JSON imports preserve an available identity or duplicate into a new identity when a record already exists. Current-project replacement is a separate explicitly confirmed operation. Unsupported/corrupt data remains raw and recoverable; no migration drops unknown metadata.

Record current measurements saves actual instrument results, current circuit and instrument settings; demo scope records retain their independent origin. This is a compact local experiment log, not a scientific calibration certificate. LocalStorage quota errors are visible and full recovery/export remains available. Imports currently have a 2 MB operational limit; no silent truncation is applied. Files are user-selected local JSON, never textbook-source uploads or website AI generation inputs. Third-party file formats, attachments, sharing and cloud transport remain deferred.

Cross-device merging has a separate pure contract. Before enabling transport, project-level deletion/restoration must carry tombstones/revisions and conflicting offline updates must retain both copies. Per-device layout/search/tool selection are not synchronized project content. A separately approved isolated backend and cost decision are still required.

Snapshot restoration never changes project identity, metadata or the snapshot/deletion collections. Unknown snapshot annotations remain preserved in their stored snapshot; only known experiment fields become active. A stored document whose embedded project identity disagrees with its key is treated as unreadable and remains exportable in raw form; saving cannot overwrite it.

Explicit saves cancel outstanding debounce timers. Completed saves update the active revision only when they belong to its captured identity. Creation, duplication, switching, import and deletion use a temporary busy/inert transition; navigation waits for completion. Delayed-local-lock desktop/phone acceptance exercises transactions longer than the autosave debounce. Real external stale-write conflicts still preserve both copies for review.
