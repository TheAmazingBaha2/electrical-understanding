# Teaching and design contract

The Workbench is a long-term guided electronics tutor. A chapter becomes as many substantial lessons as its concepts require, rather than one summary or a fixed twelve lessons. The technical limit is 40 units per source. Long material must be supplied in readable excerpts; an outline cannot recover information missing from its source extraction.

Each lesson uses Overview / Learn / Interact / Quiz / Review. Learn introduces quantities, symbols, assumptions, practical meaning and intermediate worked steps in plain English. Discussion and prediction tasks ask for the learner's reasoning before showing a debrief. Each new lesson has a model-chosen number of distinct quiz checks (technical bound 1–40, with no target of ten) and 2–8 grounded widget activities, including explanation, application, changed-condition reasoning and error diagnosis. Favor multiple-choice/selectable diagnosis, true/false options and numeric checks. Written responses are optional and limited to one per quiz; they are honest self-checks, not AI-certified grades. Numeric single-quantity answers use deterministic checking. Model-selected approved slider simulators and clickable prediction tasks are the main practice. Arbitrary generated code is never executed.

Novel source content remains in its appropriate book, exam or lab path. Useful overlap belongs in Review & Reinforcement. Pure mathematics is independent, has no subtracks, and never blocks other tracks. Model inventory comparisons are advisory, not comprehensive textbook comparisons or claims of learner mastery. Every rule, activity and question cites source evidence; book/page metadata remains visible and uncertain extraction/gaps remain disclosed.

Run scan is a user-authorized sequence of saved Sol checkpoints: teaching brief, source interpretation, flexible outline, per-unit lesson drafting and separate technical/educational review. A single huge paid chapter response is intentionally avoided because output truncation and correction would endanger the whole chapter. Every paid stage retains its atomic reservation and attempt identity. Failures halt; known IDs resume freely and invalid saved JSON can be revalidated freely. Retries and revisions are separate explicit authorizations. Running is browser-orchestrated: leave/reload and explicitly Resume; no unattended scheduling is promised.

Verify data reads the original stored file and checks saved evidence, outline, draft structure, source references and review status without paid inference. It does not independently reread/interpret the chapter, prove every formula or certify pedagogical quality. Approve is a separate free human action. Only approved inventory reaches active dashboard statistics, saved quizzes and scheduled reviews. Pending drafts never do.

Visual changes use the same inventory and stable IDs. Never rewrite stored content, alter review dates, mix production/staging projects, remove financial checks or enable paused AI endpoints as a side effect of a design edit. Chapter 3's exact approved scan remains in Legacy; future chapters route normally. Preserve all three Legacy groups and their history.

Acceptance: syntax/build/module checks and unit tests pass, affected desktop/phone Chromium scenarios pass, exact-commit CI passes before staging frontend promotion, changed Edge source is deployed/read back separately, and actual data preservation is reported. No paid AI call is implied by engineering or audit authorization.

Related uploads use the same book and optional chapter/theme label. Intake identifies a complete subsection, coherent theme, or partial continuation. Each newly registered part snapshots earlier interpreted sources in that group, preserving source job, book, original printed pages and evidence IDs under namespaced references. Sol can teach supported additions and connect earlier ideas without rewriting prior approvals, inferring mastery, or inventing unseen continuation pages. With no group label, earlier book sources provide bounded context. At most eight earlier interpreted parts are included; incomplete context is disclosed. Later uploads extend the path; they do not silently enrich an already approved lesson.
